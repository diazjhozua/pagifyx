End-to-end flow, code level

One brochure goes through five phases. Phases 1 to 4 each start with one browser request and end with a redirect. Phase 0 is the startup, which runs once when the server starts. Every step below names the function that runs it and where it lives. Use the lane colour to see which layer does the work.

0 Startup once per process create_app()
1 Read website POST /sessions read_website()
2 Plan the brochure POST /sessions/{id}/fold choose_fold()
3 Revise POST /sessions/{id}/revise revise()
4 Approve and build POST /sessions/{id}/approve approve()

Phases 2 and 3 can repeat. Revise as many times as needed, then approve. Phase 4 can run again after a revision, which clears the old download link.

Error path and locking

CaseLaneCodeWhat happens
E.1Route_attempt() web/routes.py:60Workflow errors (ScrapeError, LLMError, BrochureError) are stored on session.error. The route still redirects.
E.2StateSession.take_error() workflow/session.py:97The next page that renders shows the message once, then clears it.
E.3Routeany other exceptionNot caught. It becomes an HTTP 500. These are bugs, not user errors.
E.4Servicesession.lock in each mutating stepReading the site, choosing the fold, revising, and approving each take session.lock, so two requests for one session run one after the other. Each step computes in locals and commits its state only on success. The one exception is settings_form. The route writes it before the step takes the lock, on purpose, so a failed step keeps what the user typed. The logo file is written inside the lock, and only after the plan passes.
E.5StateSessionStore workflow/session.py:107Sessions live in a dictionary. A restart loses them. Files under output/ stay on disk.
