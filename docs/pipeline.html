How pagifyx works

pagifyx reads a company website, asks an AI model to plan a brochure, lets you change the plan in chat, and then writes a Word file. The model is called in three places: to read the site, to plan the brochure, and for each change you request. All other work is ordinary code.

The steps

Step 0 runs once when the app starts. Steps 1 to 4 run in order, from the browser. Each step is one request. The routes for steps 1 to 4 redirect to a page that shows the result. The download route returns brochure.docx itself, or redirects to the overview when no file has been built. Each track below reads left to right.

0

Start the app (once)

Starts when: you run uv run pagifyx.

  1. Start the server__main__.main, uvicorn on 127.0.0.1:8000
  2. Build the appweb/app.py create_app
  3. Read settingscore/config.py, from .env
  4. Create the model clientllm/client.py ChatClient.from_settings
  5. Create the session storeworkflow/session.py SessionStore, files under output/

Ends with: the home page, where you paste a website URL.

1

Read the website

Starts when: you submit a URL. Route: POST /sessions. The retry route, POST /sessions/{id}/retry, runs the same read.

  1. Check robots.txtreading/scraper.py scrape_site and _load_robots. A 4xx reply means no restriction. A 5xx reply or no connection stops the read.
  2. Read the homepage_read_homepage, headless Chromium. Collects text, colours, fonts, images, and logo candidates. Needs at least 200 characters of text.
  3. Capture the logo mark_capture_logo, transparent background
  4. Follow up to 5 links_crawl_nav: same-site links from the homepage nav, header, and footer, each checked against robots.txt. A page that fails is skipped.
  5. Ask the model to read the textBrochureService._analyze, SiteAnalysis. Text is capped at 12,000 characters.
  6. Download images and logo_download_assets, under a new read-<id>- file prefix. Uses og:image when no usable logo mark was captured.
  7. Collect colours and fontcore/theme.py candidate_colours, detect_font_family
  8. Save the readsession.commit_read clears the plan and deletes the previous read's files. An uploaded logo is kept.

Ends with: brand name, tagline, tone, and site facts saved. Images and logo are on disk.

2

Plan the brochure

Starts when: you submit the form. The fold is optional: blank lets the model choose. Route: POST /sessions/{id}/fold.

  1. Read the formweb/routes.py choose_fold: fold, brand, contact, colour, font, logo. The values are kept as settings_form.
  2. Check the logo uploadworkflow/service.py check_logo_upload, before any model call: 5 MB or smaller, PNG or JPEG that Word can embed
  3. Build the plan requestllm/prompts.py plan_request: analysis, images, presets, website colours, panels
  4. Ask the model for a planworkflow/service.py _ask, parsed as Overview: fold, design, panels
  5. Check the planThe chosen fold, core/folds.py check_plan, colours from the website list, core/grounding.py check_grounding. One retry if it fails.
  6. Save the logo uploadOnly when a logo was uploaded. Written as logo-upload-<8 hex>.png or .jpeg. The logo it replaces is deleted.
  7. Save the plansession.fold, overview, history, brand and theme overrides. Revisions and brochure_path are reset.

Ends with: the plan page: the fold, the style, and the panels in print order. Generated panels are marked. On failure you return to the form with the message.

3

Revise (repeat as often as you like)

Starts when: you send a change request. Route: POST /sessions/{id}/revise.

  1. Take your requestweb/routes.py revise, from the chat box. A blank request is refused.
  2. Build the requestllm/prompts.py revision_request: the change, the fixed fold, and the panel count. The chat history is sent before it.
  3. Ask the model to reviseworkflow/service.py revise, then _ask
  4. Check the replyThe same checks as step 2, with the fold fixed. One retry if it fails.
  5. Replace the overviewsession.overview, revisions (the note is added), history (the request and reply are added)
  6. Clear the old .docxsession.brochure_path is reset

Ends with: the updated overview. Any earlier brochure must be built again before download.

4

Approve and build the Word file

Starts when: you approve. Routes: POST /sessions/{id}/approve, then GET /sessions/{id}/download.

  1. Resolve the brand textworkflow/service.py brand_text, your text first
  2. Resolve the themecore/theme.py resolve_theme, your primary colour and font first. The site font is used only if this machine has it, else Calibri.
  3. Build the Word fileoutput/docx_builder.py build_brochure: preset, landscape, one table per face
  4. Save the pathsession.brochure_path, in output/<id>/
  5. Downloadweb/routes.py download, returns brochure.docx

Ends with: brochure.docx. This step makes no model call.

Where AI is used

The model does three jobs. Everything else in the pipeline is code.

StepModel callsThe model doesCode does instead
1 Read the website1, up to 2Turns the site text into brand name, tagline, tone, and facts.Browsing, robots.txt, colours, fonts, images, logo.
2 Plan the brochure1, up to 2Chooses the fold, the style, and the colours, and writes the panels.Checks the plan: fold, cover, contact rule, images, colours, numbers, and emails.
3 Revise1 per request, up to 2Rewrites the plan from your request and the chat history.Checks the reply again.
4 Approve0Nothing.Builds the .docx from the saved plan.

A model call retries once when the reply is not valid JSON for the expected shape, or when a plan fails the plan check. A failed connection or an empty reply is not retried. A read or a plan makes at most 2 calls. With one read and one plan and no revisions, the normal total is 2 calls and the worst case is 4. Each revision adds 1 call normally, and at most 2. Each extra read adds at most 2 as well.

When a step fails

Each step route passes through one helper, _attempt. It catches the three expected error types and stores the message on the session. You see the message at the top of the next page.

  • Reading errors (site blocked, robots.txt disallows the site or cannot be checked, too little text): use the paste-text fallback, POST /sessions/{id}/paste. It analyzes the pasted text, with no images, no logo, and no detected colour or font.
  • Model errors (endpoint unreachable, an empty reply, or a reply that is still invalid after the retry, including a plan that fails the plan check).
  • Input errors (no URL or text, a colour or font in the wrong form, a logo that is too large or not a PNG or JPEG, no overview to revise or approve).
Failed steps keep the old state. Steps 1 to 3 call the model first and save their results only after it succeeds. A failed step leaves the session as it was, except the settings form, which keeps the typed values on purpose. Step 1 downloads its files under a new name prefix, so older files are not overwritten. The previous read's files are deleted only when the new read is saved. A logo upload is written only after the plan succeeds.
