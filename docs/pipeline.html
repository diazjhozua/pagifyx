How pagifyx works

pagifyx reads a company website, asks an AI model to plan a brochure, lets you change the plan in chat, and then writes a Word file. The model is called in three places: to read the site, to plan the brochure, and for each change you request. All other work is ordinary code.

The steps

Step 0 runs once when the app starts. Steps 1 to 4 run in order, from the browser. Each step is one request and ends with a redirect. Each track below reads left to right.

0

Start the app (once)

Starts when: you run uv run pagifyx.

  1. Start the server__main__.main, uvicorn on 127.0.0.1:8000
  2. Build the appweb/app.py create_app
  3. Read settingscore/config.py, from .env
  4. Create the model clientllm/client.py ChatClient
  5. Create the session storeworkflow/session.py, output/ folder

Ends with: the home page, where you paste a website URL.

1

Read the website

Starts when: you submit a URL. Route: POST /sessions.

  1. Check robots.txtreading/scraper.py _load_robots
  2. Open the homepage_read_homepage, headless Chromium
  3. Follow up to 5 links_crawl_nav, same site only
  4. Collect the page factstext, colours, fonts, images, logo candidates
  5. Capture the logo mark_capture_logo, transparent background
  6. Ask the model to read the textworkflow/service.py _analyze, SiteAnalysis
  7. Download images and logo_download_assets, new file prefix
  8. Collect colours and fontcore/theme.py candidate_colours
  9. Save the readsession.commit_read: old read files removed

Ends with: brand name, tagline, tone, and site facts saved. Images and logo are on disk.

2

Plan the brochure

Starts when: you submit the form. The fold is optional: blank lets the model choose. Route: POST /sessions/{id}/fold.

  1. Read the formweb/routes.py choose_fold: fold, brand, contact, colour, font, logo
  2. Build the plan requestllm/prompts.py plan_request: analysis, presets, website colours, panels
  3. Ask the model for a planworkflow/service.py _ask, Overview: fold, design, panels
  4. Check the plancore/folds.py check_plan, core/grounding.py check_grounding, colours from the site; one retry
  5. Save the plan and historysession.overview, session.fold, session.history

Ends with: the plan page: the fold, the style, and the panels in print order. Generated panels are marked.

3

Revise (repeat as often as you like)

Starts when: you send a change request. Route: POST /sessions/{id}/revise.

  1. Take your requestweb/routes.py revise, from the chat box
  2. Build the requestllm/prompts.py revision_request, with the history
  3. Ask the model to reviseworkflow/service.py revise, then _ask
  4. Check the replycore/folds.py check_plan and core/grounding.py check_grounding; one retry
  5. Replace the overviewsession.overview, revisions, history
  6. Clear the old .docxsession.brochure_path is reset

Ends with: the updated overview. Any earlier brochure must be built again before download.

4

Approve and build the Word file

Starts when: you approve. Routes: POST /sessions/{id}/approve, then GET /sessions/{id}/download.

  1. Resolve the brand textworkflow/service.py brand_text, your text first
  2. Resolve the themecore/theme.py resolve_theme, your primary colour and font first
  3. Build the Word fileoutput/docx_builder.py build_brochure: preset, landscape, one table per face
  4. Save the pathsession.brochure_path, in output/<id>/
  5. Downloadweb/routes.py download, returns brochure.docx

Ends with: brochure.docx. This step makes no model call.

Where AI is used

The model does three jobs. Everything else in the pipeline is code.

StepModel callsThe model doesCode does instead
1 Read the website1Turns the site text into brand name, tagline, tone, and facts.Browsing, robots.txt, colours, fonts, images, logo.
2 Plan the brochure1Chooses the fold, the style, and the colours, and writes the panels.Checks the plan: fold, cover, contact rule, images, colours, and numbers.
3 Revise1 per requestRewrites the plan from your request and the chat history.Checks the reply again.
4 Approve0Nothing.Builds the .docx from the saved plan.

Each model call retries once when the reply is not valid JSON or fails the fold check. So one step makes at most 2 requests. With no revisions, the normal total is 2 calls, and the worst case is 4.

What gets saved

Everything lives on the session in memory. Only the Word file and the image files are written to disk.

Stored on the sessionSet byUsed by

brand_overrides, theme_overrides, foldStep 2Steps 3 and 4
overview, historySteps 2 and 3Overview page, steps 3 and 4

Files: the logo and images go to the session's assets folder, and the Word file goes to output/<id>/. A restart clears the sessions, but the files stay on disk.

When a step fails

Every step runs through one helper. It catches the three expected error types and stores the message on the session. You see the message at the top of the next page.

  • Reading errors (site blocked, robots.txt disallows it, too little text): use the paste-text fallback.
  • Model errors (endpoint unreachable, or the reply is still invalid after the retry).
  • Input errors (no URL or text, no overview to revise or approve).
Failed steps keep the old plan. Every step asks the model first and saves its results only after the model succeeds. Step 1 downloads its files under a new name prefix, so older files are not overwritten. The previous read's files are deleted only when the new read is saved.
